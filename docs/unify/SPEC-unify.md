## 0. 依頼と読み方

オーナー（2026-11-20）: 「PCミエルをメインUIとして、そこにパーツ暮らしの機能を統合してくれ。RPGなどはサブで良い。またパーツ暮らしに搭載されている各種ハードチェックなどの機能を現在の上位システムとして改良して統合して欲しい。」

## 4. 点検（作り直しと改良）

### 4.0 共通
- 判定は 4 段: OK／注意／要確認／**測れず**（測れずを OK に数えない）。各項目は `Value<T>` と同じく値・状態・取得元・理由を持つ。
- 結果の形 `pcm-check/1`（JSON・キーは英語）: `{format, app, kind: system|cpu|memory|storage|gpu, startedAtUtc, endedAtUtc, outcome: completed|stopped|failed, verdict, items[], notes[]}`。
  - `items[]` の各項目は**版をまたいで変えない項目 ID**（例 `system.eventlog.whea7d`）・値の型と単位・判定・根拠を持つ。測れない値は `null` と理由コード（`unsupported|denied|timeout|error|partial`）。
  - `outcome: stopped` のときも、それまでの部分結果を項目ごとに残す（終わっていない項目は `partial`）。
  - 項目は「判定する項目」と「観測だけの項目」（`info`。経過時間・総量・速度・型番・通電時間・電力など、閾値を持たない物）に分ける。どちらになるかは項目 ID ごとに固定（設計図）。
  - **総合判定 `verdict`** は**判定する項目**の判定の最も悪い物: 要確認 ＞ 注意 ＞ 測れず ＞ OK。`partial` の項目は（すでに異常を見つけていなければ）「測れず」として数える。つまり OK は**判定する項目が全部測れて OK のときだけ**。判定する項目が全部測れず（または 1 つも無い）なら「測れず」。`info` の項目は値が欠けても総合に入れない（入れると、常に測れない観測のせいで毎回「測れず」になる）。項目ごとの数（OK n・注意 n・観測 n…）も並べて持つ。
  - 項目 ID・型・単位・理由コード・停止時の部分結果・総合判定は fixture で固定する（§13）。
- `pcm-check/1` は**伏せ字済み**: シリアル・PC 名・ユーザー名・パスは入れない。記憶媒体のドライブは型番と、ローカルの基準値の中の通し番号（`disk-1` 等）でだけ指す。差分の計算は `pcm-check/1` ではなく、ローカルの基準値（§4.4）で行う。
- 置き場 `%LOCALAPPDATA%\PCMieru\checks\`。書き込みは .tmp→`Flush(true)`→置き換え。読めない履歴は**黙って初期化せず** `.bad-<UTC>` に退避して理由を出す。保持は種類ごとに最新 200 件。
- WMI・イベントログの問い合わせはすべて**問い合わせ全体の期限**（既定 5 秒）を持ち、切れたら「測れず（時間切れ）」。
- 点検は UI スレッドで I/O・GC をしない。
- 点検中は SamplerLoop の間隔を変えない（主の画面の値はそのまま）。負荷の測定は Checks が自分で持つ。

### 4.1 システム点検（パーツぐらしの SystemCheck を移す）
- 中身は同じ（OS・CPU・メモリ各枚の定格と実速度・GPU とドライバ・ディスクの健康と空き・ページファイル・直近 7 日の WHEA／disk／Ntfs／stornvme／volmgr のエラーと Kernel-Power 41）。部品の情報は Core の Hardware（SMBIOS・SetupAPI）から取り、WMI は Core に無い物だけ。
- 直す: イベントログの問い合わせのフラグ（今 0x100＝古い順を TolerateQueryErrors のつもりで使っている。TolerateQueryErrors は 0x1000）。
- 件数は**列挙が最後まで終わったときだけ確定**する。`EvtNext` の 1 回ごとの待ちとは別に問い合わせ全体の期限を持ち、期限切れ・途中の失敗・打ち切りは「測れず」（件数 0 にしない。途中までの数を件数として出さない）。

### 4.2 CPU 負荷（パーツぐらしの CpuLoadTest を移す）
- 答え合わせつきの計算・論理 CPU ごとに 1 本・BelowNormal・30 秒／2 分／5 分・判定の閾値はパーツぐらしと同じ（持続性・ばらつき・同じ効率クラスの中央値との比・実効クロック）。
- 実効クロックは**パーツぐらしと同じ式** `Processor Frequency × % Processor Performance ÷ 100`。Core の PdhSystemSampler は既に両方のカウンタを登録している（u0.2 で「片方だけ」と書いたのは誤り）。点検は読み取りの決まりを共用し、クエリは点検専用の別インスタンスにする（主の画面の採取の周期に影響させない）。
- 改良: CPU パッケージ電力（PDH の電力メーター）が読めれば記録して出す（読めなければ測れず）。電力は観測（`info`）。温度は**項目を置かず**、結果に「CPU 温度は測っていない（ドライバを使わないため）」の注記を付ける。

### 4.3 メモリ負荷（パーツぐらしの MemoryTest を移す）
- 中身は同じ（空きの一部を借りてパターンを書いて読み戻す・空きが減ったら中断）。「借りた範囲だけの検査で、全部のメモリの検査ではない」を必ず出す。

### 4.4 記憶媒体の精密点検
- 健康の読み取りは Core の既存の物（NVMe Health・SATA SMART。通常権限で試して denied なら Helper の `disk-health-all`）を使う。
- **改良: 前回の値との増分**。増えた数は根拠つきで出す（増えたこと自体を故障と言わない）。増えたときの判定は**パーツぐらしの増加時の判定表どおり**: 媒体の誤り・重大警告・ATA の不良セクタ系は「要確認」、エラーログの件数と ATA 199（CRC。ケーブルや差し込みのことが多い）は「注意」。通電時間・書き込み量・不意の電源断など自然に増える物は観測。比べられなかった増分も観測（初回は毎回そうなるので「測れず」にしない）。
  - **ローカルの基準値**を `%LOCALAPPDATA%\PCMieru\checks\baseline\` に `pcm-check/1` とは別に持つ。台の見分けはパーツぐらしの Baseline をそのまま移す:
    - 鍵 v2＝シリアル・一意 ID・型番・容量・接続。シリアルも一意 ID も無い「弱い鍵」では記録も比較もしない。
    - 一度でも同じ鍵の台が並んだ鍵は `twins.json` に残し、以後**ずっと比べない**。場所（SCSI アドレス）で分けられれば場所つきの鍵で記録だけ続ける（場所つきの鍵では比べない）。
  - **識別子の取得元**はパーツぐらしと同じにする: シリアル＝デバイス記述子（Core の StorageCollector が今読んでいる物）・一意 ID＝`IOCTL_STORAGE_QUERY_PROPERTY` の StorageDeviceIdProperty・場所＝`IOCTL_SCSI_GET_ADDRESS`。Core には今一意 ID と場所の読み取りが無いので足す（読めなければ空＝弱い鍵の判定に回る）。旧基準値の鍵と同じ文字列になることを fixture で守る（違うと移行した基準値が全部「初回」になる）。
  - **一意に対応できない台は差分を出さない**（「前回と比べられません」と理由つき）。型番とシリアルの末尾だけで見分けない。
  - 基準値は利用者の端末から出さない（ファイルにシリアルの読める部分を含むので、書き出し・AI 向けコピーには使わない）。
- **表面スキャン**（読み取りだけ・任意。**v0.4 の後**・§11）は長い管理者処理なので、Helper に**セッション**を足す:
  - 起動は今の Helper と同じ `runas`・引数固定: `PCMieru.Helper.exe scan-session --drive N --expect <台の鍵のハッシュ> --mode sample|full [--every n] --parent <pid> --parent-created <FILETIME> --pipe PCMieru.Helper.<乱数> --user-sid <SID>`。1 回の UAC で 1 ドライブ 1 走査。他の操作は受けない。
  - **始める前に対象を確かめる**: `--drive N` の番号は抜き差しで別の台に回り得るので、Helper は**読むのと同じハンドル**で識別子を取り直し、鍵のハッシュが `--expect` と一致しなければ何も読まずに終わる（終わりの結果 `target-mismatch`）。
  - **見分けられない台は走査しない**: 弱い鍵の台と、`twins.json` に載った鍵（同じ鍵の別の台があり得る）は、呼び出し側が走査を出さない（「この台は他の台と見分けられないので、表面スキャンはできません」）。Helper の側でも、開いた台の鍵が弱いときは拒否する。
  - 通信は NetMeter と同じ作法の名前付きパイプ（DACL は利用者本人だけ・両端の PID と作成時刻を照合（MeterHost の IsParent と同じ）・偽のサーバに何も送らない）。Helper → 呼び出し側: 進み具合・読めなかった範囲・終わりの結果。呼び出し側 → Helper: **Stop だけ**。
  - 決めて固定する物（設計図で数を決め、fixture で守る）: 取り決めの版・1 フレームの上限・接続の期限（来なければ何も読まずに終わる）・切断＝Stop と同じ扱い・終わりの結果の種類（`completed|stopped|stop-timeout|target-mismatch|failed`）・`--every` の単位（MiB）と範囲。
  - **止める**: ドライブは `FILE_FLAG_OVERLAPPED` で開き、Stop で `CancelIoEx`。`CancelIoEx` は**取り消しの要求にすぎない**ので:
    - 読み取りが完了（取り消しで終わった物を含む）するまで、そのバッファと `OVERLAPPED` を解放しない。
    - 画面は「止める要求を受けた」→（完了を確かめてから）「止まった」の 2 段。10 秒たっても完了しなければ「停止待ちが時間切れ（読み取りが戻りません）」と出し、待ち続ける。止まったと言わない。
    - 次のスキャンの開始は、前のセッションの完了を確かめてから。
    - 親が終わったとき・パイプが切れたときも同じ規則（要求→完了を待つ→出る）。
  - 書かない・ネットに出ない・ファイルを作らない（結果はパイプでだけ返す）。
- USB の箱・RAID で読めない物は「この接続では読めません」（unsupported）。

### 4.5 GPU 負荷
- パーツぐらしの GpuLoadTest（D3D11 の計算・答え合わせ・78℃ 以上なら始めない・83℃ で止める・温度が読めない GPU には負荷をかけない）を移すが、**コンパイル時の門は閉じたまま**。温度は SensorHost ではなく点検が自分で NVML を読む（止める判断を別プロセスの再起動に預けない）。門を開くのは実機確認の後（§12-5 で決定: オーナーの立ち会いは要らない。司会側が Win11 の RTX 5070 で、NVML の温度・クロック・電力・制限理由を 1 秒ごとに記録しながら、78℃ 以上で始まらないこと・83℃ で止まること・温度が読めないときに負荷をかけないこと・止めたら負荷が消えることを確かめる。オーナーがゲーム中は回さない）。

### 4.6 CLI と MCP
- CLI: `pcmi check system [--json]`・`pcmi check storage [--elevate] [--json]`（増分つき）・`pcmi check history [--json]`。負荷の点検と表面スキャンは GUI だけ（端末から長い負荷を気軽にかけさせない）。
- MCP: 読み取りだけの `get_check_history`（過去の結果）を足す。`run_system_check`（その場で数秒の点検）は v0.4 の後（§11）で、足すときも**履歴に保存しない・UAC を出さない**（denied の項目は測れずのまま返す）。**負荷・表面スキャン・記録の開始は MCP に出さない。**

## 5. テストの記録（パーツぐらし feature/sensor-log を作り直す）

- 源は **Core の SamplerLoop と SensorHost**。記録が独自に PDH・NVML・ADLX を開かない。
- **1 秒の要求**: 記録は開始時に SamplerLoop へ「1 秒で回して」の要求を取り、停止・失敗・窓を閉じたときに必ず返す（要求は数えて持ち、最後の 1 本が返ったら元の間隔に戻る）。記録中は、主の窓の一時停止や最小化よりこの要求が優先する（採取は続け、表示の更新だけ止まる）。
- 足りない項目は共通の収集側に足す: CPU パッケージ電力（PDH 電力メーター）・GPU の制限理由（NVML の clocks event reasons）・AC／電池。足した物は主の画面にも出る。
- **鮮度**: SensorHost は 2 秒周期で再起動の間に空白があり得る。記録は値ごとに**取った時刻**を持ち、同じフレームの再掲は「再掲」と印を付けて新しい値として数えない。空白は欠落として残す。
- 置き場 `ドキュメント\PCMieru\runs\`（利用者が見つけられる所）。形式 `pcm-run/1` はパーツぐらしの `partslife-run/1` を元に、**値ごとの取得時刻と再掲の印を足した物**（中身は同じではない。旧形式は読めるようにする）。CSV は 10 秒ごとと停止時に `Flush(true)`。
- 改良: 記録中も空きを見て 200MB を切ったら止める・一覧から消せる。保持の上限（最新 50 件と合計 2GB の小さい方を超えたら古い物から消すかを停止時に尋ねる）は v0.5 の後（§11）。
- 要約の規則（負荷あり 50%・持続値は最後の 1/3・30 秒窓で温度 +3℃ かつクロック −5% を「同時に起きた」・制限理由の秒数・印の区間）の閾値はパーツぐらしと同じ。
- ただし**秒数は取得時刻から数える**（パーツぐらしは「該当サンプル数 × 固定周期」。2 秒ごとの GPU 値を 1 秒の記録に載せて再掲を除くと半分になるため）: 新しい値はそれぞれ次の新しい値の取得時刻まで続いたと見なす。間が名目周期の 3 倍を超えたら、その先は欠落（分子にも分母にも入れない）。欠落の合計秒は要約に出す。
- AI 向けコピー（`pcm-ai-export/1`。v0.5 の後）: 前文・要約・最大 48 点・項目辞書。伏せ字は PCミエル共通の redactor を通してから、パーツぐらしの最後の関門（ExportGuard）も残す。送信機能は持たない。

## 6. 書き出し

| 形式 | 出す所 | 読む所 | 統合での扱い |
|---|---|---|---|
| `PCB1.` + base64url(JSON v1) と同じ JSON のファイル | 「PCの構成」の「構成コードをコピー」・`pcmi parts --code` | web-autoai `/my-config` | パーツぐらしの BuildCollector／BuildRules／BuildCode を Checks に移す。**同じ PC で同じ文字列が出る**ことを試料で守る（パーツぐらし v0.7.4 の出力を golden に）。`src` は `"parts-life"` のまま（サイトの受け口を変えない。変えるなら受け渡し側と同時） |

- 2 つを片方から作らない（PCB1 には光学ドライブなど、pcm-parts/1 には NVML の観測値があり、通すと欠ける）。共通にするのは型番の取得結果まで。

## 7. 自動更新（パーツぐらしの方式を土台に、配布一式へ広げる）

- 宛先・検証はパーツぐらし v0.7.4 と同じ（許可した GitHub の宛先だけ・同じ Release の SHA256.txt と一致・タグと埋め込みの版が一致して新しい・ダウングレードしない・draft/prerelease は見ない）。repo は `goemon0000/pc-mieru`。
- **信じる物の線**: SHA256.txt は同じ Release から来るので、これは「GitHub の持ち主を信じる」方式で、改ざんの検出ではなく壊れた取得の検出。README にそう書く。

### 7.1 ZIP の作法（クライアント側で決める）
パーツぐらしの updater は ZIP の直下に固定名 2 ファイルを求める。PCミエルの ZIP は最上位に配布フォルダ `PCMieru-<版>-win-x64/` を含む（publish.ps1）。このずれを埋めるため、**ZIP の形はクライアントのコードに書き、Release の中身だけには預けない**:
- ルートはちょうど 1 つのフォルダ `PCMieru-<タグの版>-win-x64/`。その外の項目・絶対パス・`..`・ドライブ名・代替データストリーム名・重複名（大小文字無視）があれば入れない。
- **必須ファイル**（クライアントの版に埋め込んだ一覧。今は `PCMieru.exe`・`pcmi.exe`・`PCMieru.Core.dll`・SensorHost・Helper・NetMeter。足した版で一覧も足す）が全部あること。
- 中に入っていてよいのは、クライアントが許す名前（拡張子 exe・dll・json・txt・md・pdb と、拡張子の無い `LICENSE`）で、かつ Release の版ごとの許可リスト（manifest）に載っている物だけ。両方を満たさなければ入れない。許す名前の一覧は `publish.ps1` の出力と突き合わせる試験を持つ（配布に足した物が許されず更新が止まる、を CI で先に見つける）。
- **manifest に載った物は全部そろっていて、ハッシュが一致すること**。クライアントに埋め込んだ必須ファイルは「最低これだけ」の床で、次の版で増えた物（v0.6 の Party 等）の欠けは manifest の側で見つける。manifest は同じ Release から来るので、信じる線は SHA256.txt と同じ（上の「信じる物の線」）。
- **消してよい物**: 入れたときに書いた**導入記録**（`update\installed.json`＝その版で置いたファイル名とハッシュ）に載っている物だけ。利用者が置いた物・記録に無い物は消さない。

### 7.2 交換と戻し
- **起動の門**: 配置フォルダごとの門を、GUI・pcmi（CLI／MCP）・SensorHost・Helper・NetMeter・Party の全部が起動時に「共有」で取り、更新の交換は「専有」で取る。全部が止まったと確かめられなければ交換を延ばす。
  - 門は**パス表記によらず同じ配置に 1 つ**: 名前つきのカーネル物ではなく、配置フォルダの中のファイル（例 `update\gate`）を共有読み取りで開いて持つ形を第一候補にする（短い名前・大小文字・ジャンクション越しでも同じ実体を開く。`runas` で別の管理者アカウントとして動く Helper・NetMeter も、フォルダが読めれば同じ門に届く）。設計図で確定する。
  - **門が取れない・journal の後始末が済んでいない・後始末に失敗した**ときは、どの exe も本来の仕事を始めない（GUI は理由を出す。Helper・NetMeter は何もせずに終わる）。
- 交換は別プロセス。**電断から戻れる記録**（`update\journal.json`。段ごとに書いてから動く）を持ち、旧一式を `update\prev-<版>\` に丸ごと残す。巻き戻しは「足した物を消す」と「消した物を戻す」の両方。
- **起動の確かめ**: パーツぐらしの 15 秒の生存確認・3 回で戻す・その版を二度と入れない、を一式に広げる。GUI が 15 秒生きているだけでは足りないので、起動時に補助の exe と DLL が**同じ世代**（版とビルドの印が導入記録と一致）かを確かめ、違えば戻す。
- 交換を延ばす条件: 門が取れない（上のどれかが動いている）・点検・記録が動いている・利用者が操作中。延ばしたら次の機会に。
- 書けないフォルダ（Program Files 等）では「知らせるだけ」。

### 7.3 モードと署名
- モード: 自動／知らせるだけ／切る。**既定は初回に尋ねる**（推しの選択肢として「知らせるだけ」を選んだ状態で出す。尋ねる前は通信しない）。**未署名の版を利用者の操作なしで入れるのは、利用者が「自動」を選んだときだけ**（§12-4 で決定）。
- 署名: 今は未署名。署名を始めるときは、署名者（証明書の拇印でなく発行先の名前と発行者の組）を**クライアントのコードに埋め込む**（最初に来た版を信じる形にしない）。以後の版は Helper・NetMeter を含む全 exe・DLL の署名者の一致を必須にし、未署名に戻る更新は入れない。

### 8.2 PCミエルの初回（引き継ぎ）
- 探し順はパーツぐらしの読み込みと同じ: `%APPDATA%\PartsLife\state.json`、無ければ `%APPDATA%\PartsParty\state.json`（旧名）。あれば「パーツぐらしの続きを引き継ぐ」を尋ねる。
- **旧版が動いていたら引き継がない**: v0.7.4 は上の Mutex を持たないので、`PartsLife.exe` のプロセスを見て、動いていれば「パーツぐらしを終了してから引き継ぎます」と出して保留する（勝手に終わらせない）。
- はいなら物語・レベル・冒険・表示の設定を `%APPDATA%\PCMieru\party\state.json` へ**写す**:
  - 元は**読み取りだけ**で開く（書き込み中の旧版と争わない共有の指定）。元は消さない・書き換えない。
  - 写し先が既にあれば**上書きしない**（「既に引き継いであります」）。途中で失敗したら写し先の書きかけを捨て、やり直せる。
- 点検のデータ（`%APPDATA%\PartsLife\checks\`）: v0.7.4 が残すのは**ディスク別の基準値（BaselineHistory）と `twins.json` だけ**（点検の結果そのものは保存していない）。これを鍵と重複の判定を保ったまま**ローカルの基準値**（§4.4）へ写す。`pcm-check/1` の履歴は引き継がない（元が無い）。変換の fixture は v0.7.4 の実際のファイルの形で v0.4 に用意する（§11）。
- **ログオン起動**: 旧の値は HKCU Run の `PartsLife`。Windows の承認（`StartupApproved\Run`）は**値の名前ごと**で、新しい名前の値は承認の印が無いと有効扱いになる。だから:
  - 旧の値の承認が有効と読めたときだけ、自動起動を引き継ぐかを尋ねる。無効・不明・読めないときは引き継がない（新しい値を書かない。旧の値はそのまま）。
  - 「はい」なら**引き継ぎが成功してから**、新しい値（Party）を書き、旧の値とその承認の印を外す。途中で失敗したら新旧の両方を元に戻す（承認の読み書きは PCミエルの既存の StartupApproved の部品を使う）。

### 8.3 repo とページ
- GitHub `goemon0000/parts-life` の扱い: 名前「パーツぐらし」は PCミエルの中の機能名として残す。repo は v0.8.0 の README で PCミエルを指し、v0.8.0 の 1 か月後に archive（それまでは Issues を受ける）（§12-1・2 で決定）。web-autoai の `/parts-life` ページの書き換えは受け渡し側の仕事（ここからは依頼書を渡すだけ）。

## 13. 試験

- 移した物は元の試験も移す（パーツぐらし Core 約113・Update 約142・Checks・記録の約85）。
- `pcm-check/1`: 項目 ID・型・単位・理由コード・停止時の部分結果・総合判定（全部測れず・一部測れず・停止・観測だけが欠けても OK になること）を fixture で固定。旧の基準値と twins の変換も v0.7.4 の実ファイルの形の fixture で（旧と同じ鍵の文字列になること）。
- 記憶媒体の増分: 同じ鍵の台が 2 つ・過去に twins になった鍵・弱い鍵・抜き差しで番号が回った台で、差分を出さないこと。走査を出さないこと。
- イベントログ: 期限切れ・途中の失敗で件数を出さないこと（偽の列挙で）。
- PCB1・pcm-parts/1: パーツぐらし v0.7.4 と v0.3.0 の出力を golden にして同じ入力から同じ文字列。サイトの実パーサーでの受け入れは受け渡し側で（§6）。
- Helper のセッション: 偽のパイプで進み具合・Stop・完了待ち・停止待ちの時間切れ・切断・親の終了・対象の不一致・フレームの上限を CI に。実際の表面スキャンと UAC は RealMachine。
- 移行: state.json の試料（壊れた物・旧 PartsParty 名・未知の欄・写し先が既にある・旧版が動いている）を写して、元が変わらないこと・写し先が読めること・やり直せること。Run の値（無効にしてある・承認が読めない・途中で失敗した）で新旧とも元のままになること。
- 自動更新: パーツぐらしの `update-dry-run.py`（偽の GitHub）を一式の交換に広げる。ZIP の作法の違反（ルートが違う・`..`・必須が無い・manifest に載った物が欠ける・許可外）で入れないこと。`publish.ps1` の出力が許す名前に収まること。別のパス表記で起動した exe も同じ門を取ること。交換の途中で止めた（電断の代わり）ときに journal から戻ること。補助の exe が古い世代のときに戻すこと。v0.6 相当の ZIP を v0.5 が入れて戻せること。
- 記録の要約: 2 秒ごとの値と 1 秒の記録・再掲・欠落の試料で、秒数が取得時刻どおりになること。
- 画面: 点検の各タブを smoke の写しに。codex（gpt-6.1-terra）に写しと実物を見せる。
