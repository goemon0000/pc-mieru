## 0. 依頼と読み方

オーナー（2026-11-20）: 「PCミエルをメインUIとして、そこにパーツ暮らしの機能を統合してくれ。RPGなどはサブで良い。またパーツ暮らしに搭載されている各種ハードチェックなどの機能を現在の上位システムとして改良して統合して欲しい。」

- **主の画面＝PCミエルの窓**。点検の開始・進み具合・結果・履歴は全部 PCミエルの画面から扱える。
- **RPG はサブ**＝導線の優先順位。PCミエルから開ける従の窓で、既定では常駐しない（利用者が選べば常駐）。
- **「上位システムとして改良」**＝点検を PCミエルの計測基盤（Core の Snapshot・SensorHost・Helper）の上で作り直し、品質を上げる: 取れない物を取れたと言わない・前回からの差分・止めたら確実に止まる・長い処理でも窓が固まらない・結果が CLI と AI からも読める。
- 順番: この統合の後に BTO 参考ガイド（web-autoai `/tools/power-check`）との連携。

## 1. 守る物（変えない）

- SPEC v0.2 の §1（asInvoker・自前のドライバ無し・制御しない）・§3（`Value<T>`）・§8（操作と安全）・§10（MCP は読み取りだけ）。
- **書き出しの 2 形式はどちらも互換を切らない**（§6）: パーツぐらしの構成コード `PCB1.`（`/my-config` が読む）と `pcm-parts/1`（`/tools/power-check` が読む）。`pcm-parts/1` の形を変えるときは先に電力の段（6746a72f）へ知らせる。
- パーツぐらしの物語・レベル・冒険の保存（state.json）を失わせない（§8）。
- GPU 負荷はオーナー立ち会いの実機確認まで切ったまま（コンパイル時の門）。

## 2. 構成（足す物）

```
PcMieru.Checks.dll        UI なしの点検・記録・要約・構成コード PCB1。Core を参照（新規）
PCMieru.Party.exe         パーツぐらしの窓（WPF・通常権限）。RPG と常駐のドット絵。Core と Party.Core を参照（新規・従）
PcMieru.Party.Core.dll    物語・レベル・冒険・保存の規則（パーツぐらし PartsLife.Core を移す。UI なし・Linux でも試験可）
PcMieru.Update.dll        自動更新（パーツぐらし PartsLife.Update を移す）
PCMieru.Helper.exe        既存。長い読み取り処理のための「セッション」を足す（§4.4）
```

- 管理者で動く exe は **Helper と NetMeter の 2 本のまま**（パーツぐらしの PartsLife.Check.exe は持ち込まない）。
- `PCMieru.Party.exe` を WPF の別 exe にする理由: パーツぐらしの描画（DrawingVisual）と規則をそのまま使える・主の窓に WPF を読み込まない。捨てた案は decisions の 11-20。
- Party は **自分のプロセスで Core の SamplerLoop を使う**（パーツぐらし独自の PDH・D3DKMT・WMI の採取は捨てる）。主の窓と同時に開いていると採取が 2 本になるのは許す（共有は SPEC v0.2 §9 の「GUI と CLI のスナップショット共有」と同じ v1.x の課題）。Party の採取は表示に要る物だけ（プロセス一覧を取らない・GPU 温度は SensorHost を起こさない）。
- 配布は従来どおり ZIP 1 本。Party は WPF のランタイムを要するので、配布一式は WPF を含む自己完結になる。**増える大きさを測って §10 に書く**。

## 3. 画面（主の窓に足す物）

左のナビに **「点検」** を足す（「診断」の上）。中は上のタブで:

1. **システム**（§4.1）: 「点検する」1 押しで数秒。結果は項目ごとの 4 段（OK／注意／要確認／測れず）と根拠。
2. **負荷**（§4.2・§4.3）: CPU／メモリ（GPU は門が開くまで出さない）。時間 30 秒／2 分／5 分。進み具合・今の速さ・止めるボタン。
3. **記憶媒体**（§4.4）: ドライブごとの健康と**前回からの増分**（例「メディアエラー 1,204 → 1,227（+23）」）・任意の表面スキャン（間引き／全面）。
4. **テストの記録**（§5）: 記録の開始・印・停止・一覧・要約・AI 向けコピー。
5. **履歴**: 上の結果の一覧（日時・種類・判定）。開くと当時の結果。

- 点検は**タブを移っても続く**（主の窓を閉じたら止める。閉じる前に「点検が動いています。止めて閉じますか」）。
- 「概要」の「気づいたこと」に、直近の点検の要確認と記憶媒体の増分を出す（新しい観察の規則。根拠と日時つき）。
- 「PCの構成」に **「構成コードをコピー（/my-config 用）」** を足す（`型番だけコピー（サイト用）`＝pcm-parts/1 の隣）。押すと中身を見せてからコピー（pcm-parts/1 と同じ作法）。JSON で保存も。
- **パーツぐらしの入口**: ナビの一番下に「パーツぐらし」（押すと Party を起こす。既に動いていれば前に出す）。設定に「ログオン時にパーツぐらしを起動」（既定オフ・HKCU Run）。
- 画面の写し（`--smoke --shots --fakes`）に点検の各タブを足す。偽の結果で全段の判定が写る。

## 4. 点検（作り直しと改良）

### 4.0 共通
- 判定は 4 段: OK／注意／要確認／**測れず**（測れずを OK に数えない）。各項目は `Value<T>` と同じく値・状態・取得元・理由を持つ。
- 結果の形 `pcm-check/1`（JSON・キーは英語）: `{format, app, kind: system|cpu|memory|storage|gpu, startedAtUtc, endedAtUtc, outcome: completed|stopped|failed, verdict, items[], notes[]}`。シリアル・PC 名・ユーザー名・パスは入れない（記憶媒体はドライブを型番＋マスクしたシリアルの指紋で見分ける）。
- 置き場 `%LOCALAPPDATA%\PCMieru\checks\`。書き込みは .tmp→`Flush(true)`→置き換え。読めない履歴は**黙って初期化せず** `.bad-<UTC>` に退避して理由を出す。保持は種類ごとに最新 200 件。
- WMI・イベントログの問い合わせはすべて時間切れ（既定 5 秒）を持ち、切れたら「測れず（時間切れ）」。
- 点検は UI スレッドで I/O・GC をしない。
- 点検中は SamplerLoop の間隔を変えない（主の画面の値はそのまま）。負荷の測定は Checks が自分で持つ。

### 4.1 システム点検（パーツぐらしの SystemCheck を移す）
- 中身は同じ（OS・CPU・メモリ各枚の定格と実速度・GPU とドライバ・ディスクの健康と空き・ページファイル・直近 7 日の WHEA／disk／Ntfs／stornvme／volmgr のエラーと Kernel-Power 41）。部品の情報は Core の Hardware（SMBIOS・SetupAPI）から取り、WMI は Core に無い物だけ。
- 直す: イベントログの問い合わせのフラグ（今 0x100＝古い順を TolerateQueryErrors のつもりで使っている）。問い合わせに失敗したログは「測れず」で、件数 0 にしない。

### 4.2 CPU 負荷（パーツぐらしの CpuLoadTest を移す）
- 答え合わせつきの計算・論理 CPU ごとに 1 本・BelowNormal・30 秒／2 分／5 分・判定の閾値はパーツぐらしと同じ（持続性・ばらつき・同じ効率クラスの中央値との比・実効クロック）。
- 改良: 実効クロックの PDH を Core の PdhSystemSampler と同じ読み方に揃える。CPU パッケージ電力（PDH の電力メーター）が読めれば記録して出す（読めなければ測れず）。温度は測れず（理由: ドライバを使わない）。

### 4.3 メモリ負荷（パーツぐらしの MemoryTest を移す）
- 中身は同じ（空きの一部を借りてパターンを書いて読み戻す・空きが減ったら中断）。「借りた範囲だけの検査で、全部のメモリの検査ではない」を必ず出す。

### 4.4 記憶媒体の精密点検
- 健康の読み取りは Core の既存の物（NVMe Health・SATA SMART。通常権限で試して denied なら Helper の `disk-health-all`）を使う。**改良: 前回の値との増分**（パーツぐらしの Baseline を移す）。増えた数は根拠つきで「要確認」（増えたこと自体を故障と言わない）。
- **表面スキャン**（読み取りだけ・任意）は長い管理者処理なので、Helper に**セッション**を足す:
  - 起動は今の Helper と同じ `runas`・引数固定: `PCMieru.Helper.exe scan-session --drive N --mode sample|full [--every n] --parent <pid> --parent-created <FILETIME> --pipe PCMieru.Helper.<乱数> --user-sid <SID>`。1 回の UAC で 1 ドライブ 1 走査。他の操作は受けない。
  - 通信は NetMeter と同じ作法の名前付きパイプ（DACL は利用者本人だけ・両端の PID と作成時刻を照合・偽のサーバに何も送らない）。Helper → 呼び出し側: 進み具合・読めなかった範囲・終わり。呼び出し側 → Helper: **Stop だけ**。
  - 止める: ドライブは `FILE_FLAG_OVERLAPPED` で開き、Stop で `CancelIoEx`。「止める要求を受けた」と「止まった」を分けて出す。I/O が 10 秒戻らなければ「止まらない読み取りがあります」と出し、Helper は終わり次第出る。親が終わったら Helper も止まる。
  - 書かない・ネットに出ない・ファイルを作らない（結果はパイプでだけ返す）。
- USB の箱・RAID で読めない物は「この接続では読めません」（unsupported）。

### 4.5 GPU 負荷
- パーツぐらしの GpuLoadTest（D3D11 の計算・答え合わせ・78℃ 以上なら始めない・83℃ で止める・温度が読めない GPU には負荷をかけない）を移すが、**コンパイル時の門は閉じたまま**。温度は SensorHost ではなく点検が自分で NVML を読む（止める判断を別プロセスの再起動に預けない）。門を開くのはオーナー立ち会いの実機確認の後。

### 4.6 CLI と MCP
- CLI: `pcmi check system [--json]`・`pcmi check storage [--elevate] [--json]`（増分つき）・`pcmi check history [--json]`。負荷の点検と表面スキャンは GUI だけ（端末から長い負荷を気軽にかけさせない）。
- MCP: 読み取りだけの `get_check_history`（過去の結果）と `run_system_check`（数秒・読み取りだけ）を足す。**負荷・表面スキャン・記録の開始は MCP に出さない。**

## 5. テストの記録（パーツぐらし feature/sensor-log を作り直す）

- 源は **Core の SamplerLoop と SensorHost**（記録中は 1 秒を要求する。主の画面の表示間隔とは独立）。記録が独自に PDH・NVML・ADLX を開かない。
- 足りない項目は共通の収集側に足す: CPU パッケージ電力（PDH 電力メーター）・GPU の制限理由（NVML の clocks event reasons）・AC／電池。足した物は主の画面にも出る。
- SensorHost は 2 秒周期で再起動の間に空白があり得る。記録は値ごとに**取った時刻と鮮度**を持ち、同じフレームの再掲を新しい値として数えない。空白は欠落として残す。
- 置き場 `ドキュメント\PCMieru\runs\`（利用者が見つけられる所。形式はパーツぐらしの `partslife-run/1` を `pcm-run/1` に改名し中身は同じ）。CSV は 10 秒ごとと停止時に `Flush(true)`。
- 改良: 記録中も空きを見て 200MB を切ったら止める・**保持の上限**（最新 50 件と合計 2GB の小さい方。超えたら古い物から消すかを停止時に尋ねる）・一覧から消せる。
- 要約の規則（負荷あり 50%・持続値は最後の 1/3・30 秒窓で温度 +3℃ かつクロック −5% を「同時に起きた」・制限理由の秒数・印の区間）はパーツぐらしと同じ。
- AI 向けコピー（`pcm-ai-export/1`）: 前文・要約・最大 48 点・項目辞書。伏せ字は PCミエル共通の redactor を通してから、パーツぐらしの最後の関門（ExportGuard）も残す。送信機能は持たない。

## 7. 自動更新（パーツぐらしの方式を持ってくる）

- 宛先・検証はパーツぐらし v0.7.4 と同じ（許可した GitHub の宛先だけ・同じ Release の SHA256.txt と一致・タグと埋め込みの版が一致して新しい・ダウングレードしない・draft/prerelease は見ない）。repo は `goemon0000/pc-mieru`。
- 交換の単位は**配布一式**（exe 群と DLL）。版ごとの許可リスト（中に入っていてよいファイル名）を Release に置き、ZIP の中身がそれと一致しなければ入れない。
- 交換は別プロセスで一式を入れ替え、新しい版が起動して確認できなければ一式を戻す（パーツぐらしの 15 秒の生存確認・3 回で戻す・その版を二度と入れない、を一式に広げる）。
- 交換を延ばす条件: 点検・記録が動いている・NetMeter が動いている・同じフォルダの pcmi（CLI／MCP）や Party が動いている・利用者が操作中。延ばしたら次の機会に。
- モード: 自動（既定）／知らせるだけ／切る。書けないフォルダ（Program Files 等）では「知らせるだけ」。
- 署名: 今は未署名＝GitHub の持ち主と SHA256 を信じる方式（README に書く）。署名を始めたら、それ以降の版は署名者の一致を必須にする（未署名に戻る更新は入れない）。

## 8. パーツぐらし利用者の移行

- **パーツぐらし最後の版（v0.8.0）**: 自動更新で届く。1 回だけ「パーツぐらしは PCミエルの一部になりました」と案内し、PCミエルの紹介ページを開くボタンを出す。勝手に PCミエルを入れない。v0.8.0 自体は動き続ける（以後の更新は無い）。
- **PCミエルの初回**: `%APPDATA%\PartsLife\state.json` があれば「パーツぐらしの続きを引き継ぐ」を尋ねる。はいなら物語・レベル・冒険・表示の設定を `%APPDATA%\PCMieru\party\state.json` へ**写す**（元は残す・やり直せる）。点検の履歴（`%APPDATA%\PartsLife\checks\`）は `pcm-check/1` に変換して写す。
- パーツぐらしのログオン起動（HKCU Run）が残っていれば、「パーツぐらしの代わりに PCミエルのパーツぐらしを起動する」を尋ねて差し替える。
- 同時に動かさない: Party とパーツぐらし（旧）が同時に起動したら、後から来た方が「もう一方が動いています」と出して閉じる（同じ名前の Mutex）。
- GitHub `goemon0000/parts-life` は最後の版の後に README で PCミエルを指して archive（オーナーに確認・§12）。web-autoai の `/parts-life` ページの書き換えは受け渡し側の仕事（ここからは依頼書を渡すだけ）。

## 9. パーツぐらしの窓（Party）

- 中身はパーツぐらし v0.7.4 の常駐の窓（タブ・物語・ボード・詳細）と同じ。言語は PCミエルの設定に従う（Party 単独で起きたときは自分の設定）。
- 「操作を受けない」の意味はパーツぐらしと同じ＝**ゲームとして選ばせたり育てさせたりしない**（窓のドラッグ・拡大・メニューは受ける）。入力を透過する窓にはしない。
- 点検ボタンは Party に置かず、「点検を開く」で主の窓の点検タブを開く（点検は主の窓だけ）。
- 直す: タイマーの失敗が累計 61 回で永久に止まる→間を空けて作り直す（止まったことを窓に出す）・保存の失敗を握りつぶす→窓に出す・ディスクの種類を起動時 1 回だけ取る→Core の機器の変化で取り直す。

## 10. 軽さ（SPEC v0.2 §11 に足す）

- 測る形を 3 つに分ける: 主の窓だけ／Party だけ（常駐の形）／両方。各々 GUI と SensorHost の合計も。
- §11 の目標（private 100MB 未満・定常 CPU 0.3% 未満・warm 起動 1 秒未満）は「主の窓だけ」に当てる。Party の目標は**パーツぐらし v0.7.4 を実測して、それより重くしない**。
- `tools/measure.ps1` をこの統合で作る（§11 の手順どおり）。測るまで数字を外に書かない。配布物の大きさも v0.2.0（ZIP 51.6MB）と比べて書く。
